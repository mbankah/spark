Three moves

1

One Start per block (built)

A block has one hold to start it. Its type picks the engine: study runs the cycle, a routine runs its own steps, anything else is a plain run. It writes one run record, and the Coach, Count, Guard and every screen read that.

2

One door for change (built)

Late, over, came up, a new deadline, a day off, the library, a file and a week or period are all said in one place, Change the plan, and each shows what it does, what it costs and applies it. The wake time now moves the morning too. Still to do: a block carrying its own steps so the runner page can go.

3

Fewer, plainer screens

Setup becomes five groups and loses its action cards. Work it out becomes Right now. Reminders become one list.

Decisions made

  1. A held start earns a small reward.2 minutes of earned open phone, for the first 5 starts of a day, so at most 10 minutes. It is not proof and earns nothing in the money guide.
  2. When a study block ends mid-cycle, Spark asks.Stop the cycle, let it run on, or move the rest of the day. The asking is a confirmation system: anything else that needs confirming raises a question and gets the Home card and the lock-screen buttons without more being built.

Each system and its parts

One picture per system: what is inside, what comes in, and what leaves. Boxes with a dashed edge belong to another system and are shown only to say where the arrow goes.

Plan · What is on, and when

Owns the calendar. Reads: Change (edits), Count (tasks to place), Night (anchors). Writes: the one answer slotsFor, read by Do, Guard and every screen.

Change · How the plan moves

Owns the ways of editing the plan and what each one costs. Reads: nothing but you. Writes: the Plan, through one reflow engine, then refreshes Guard and the alarms.

Do · What you do in a block

Owns starting, running and finishing a block. Reads: the block from Plan. Writes: proof to Count, a gate to Guard, prompts to the Coach. This is where the systems fail to meet most.

Count · What it is worth

Owns minutes, the Buffer, money, earned access and the Doors pool. Reads: proof from Do, sleep from Night. Writes: missed work back into Plan, access into Guard.

Guard · What is closed to you

Owns the blocking answer and everything that enforces or loosens it. Reads: Plan, Night, Count, Do. Writes: what the phone and PC will open.

Night and morning · Sleep, wake, ready

Owns sleep, the night cutoff, the alarm and the morning photos. Reads: anchors from Plan. Writes: the wake key (the weak link), social closed, short-sleep factors.

Context · Where and when you are

Owns places, the location fix, the trusted clock and the day type. It only gives; no other system writes into it.

VRNPM: what it has to answer

You asked for the settings to be precise about what happens in each circumstance. The ledger rows VR1 to VR14 say how the cycle runs when nothing goes wrong. They do not say what to do in these cases, so the app does whatever the code happens to do. Each needs a decision before more settings are added.

CircumstanceWhat the code does todayDecision needed
The block ends while a cycle is runningThe cycle keeps running. It is looked up across yesterday and today, so it can run after the block.Stop, run on, or offer to move the rest of the day?
The cycle is longer than the blockNever compared. Starting a cycle does not read the block's length or time, only your settings.Shrink it, warn, or start at the step that fits?
You start lateThe Run card says so at 5 minutes and offers to slide the day. The cycle does not.Should a late cycle say so and offer the same slide?
A step is skippedOnly V and R can be skipped, and only by the override setting for the whole cycle.Skip one step on the day, with a reason?
Pause is longTime paused is not counted and is shown. There is no limit.After how long does a pause become a missed block?
The phone restartsThe cycle is stored, so it survives. The step-end alarm was not checked after a restart.To be tested on the phone.

The check every new feature has to pass

From now on each request gets these seven answers before any code, and they go into the ledger row for it. If an answer is "it adds a second one", the feature is joined to the existing one or it waits for your word.

  1. Which system owns it?One only. If two seem to, one is a surface.
  2. What does it read and write?Draw the arrows on the map before writing code. An arrow with no label does not go in.
  3. Where is it shown?List every surface. All read the one stored value; none keeps its own copy.
  4. What starts it and what stops it?Does that also tell the Coach, Count, Guard and the strip? If not, it is a second start.
  5. What does it replace?A new card, button or setting needs an old one folded or removed in the same change.
  6. What happens when the block ends, the day moves, the phone restarts or you pause?Write the answer into the ledger row, not just the happy path.
  7. How is it proven?One test that drives the real app through the new arrows, not a test of the part alone.
